# 播放器适配服务器 API v2

日期：2026-10-22。目标：连接音乐服务器 0.10.0，保留播放器按需下载、SHA-256 校验、取消与离线播放能力。共享歌单、上传及服务器管理功能不在播放器本期范围内。

播放器使用账号所属的只读 API Key。用户先在管理网页完成首次改密，创建 Key，选择本人歌单或显式授权系统 library，并授予 library:read 与 media:read；客户端继续用 Windows DPAPI 保存密钥。

## 实施顺序

- [x] P01 协议与错误处理：切换全部读取、媒体和封面到 /api/v2，校验连接响应，显示账号停用/Key失效、权限不足、未授权或下架、并发限额提示；不回退旧接口。
- [x] P02 游标同步：完整读取分页，原子合并快照/增量、reset和删除；保留歌单UUID/顺序/备注，支持空授权、权限收缩、409 SYNC_RESTART有界重试和取消；仅网络故障允许回退已提交快照。
- [x] P03 缓存和播放一致性：新协议使用独立缓存命名空间；曲目缺失/下架显示占位并跳过播放/下载；授权失败和成功刷新后不保留可用的旧远程入口，账户/Key切换隔离；已下载字节不作为当前授权的替代依据。
- [x] P04 页面、真实服务验收与交付：更新设置说明和适配版本，验证最新服务器创建的Key、歌单/分页、播放/封面/歌词、撤销/停用/重启用、下架恢复和离线边界；构建、回归、本地提交与最终程序提交号一致。

每项实现及验证后再勾选。只提交本次客户端源码、测试和文档，不提交 Key、密码、数据库、媒体、运行数据或产物；未经要求不推送。

## 文件职责

- RemoteLibraryClient.h/.cpp：v2 DTO、HTTP状态、游标与原子快照、缓存许可/可用性校验。
- RemoteLibraryManager.h/.cpp：本地关联歌单、播放绑定、离线任务和权限变化后的远程入口处理。
- ServerSettingsDlg.cpp、ServerLibraryDlg.cpp、RemoteLibraryVersion.h：设置指导、空授权和不可用状态、适配版本。
- Player.cpp：必要的远程列表刷新、失效入口与当前播放状态处理。
- UnitTest/remote_library_cache.cpp、remote_library_fixture.py、remote_playback_desktop.py：协议、故障及桌面回归，fixture严格使用v2。
- UnitTest/ 新增真实服务器集成验证：仅使用临时媒体/数据库及独立进程，不修改8080实例或个人账号。

## 验收重点

1. 测试先证明旧实现无法访问v2，再逐项覆盖多页快照/增量、跨页reset、游标持久化、排序/备注、空授权及失败不覆盖已提交快照。
2. 401/403不能伪装成离线成功；网络中断可使用最后成功快照。已知失效后阻止旧的远程歌单/缓存入口，重新启用或重新授权后通过成功同步恢复。
3. 软删除只删除可用曲目缓存索引，不删私人歌单成员或备注；显示最小占位，恢复后重新可播放。
4. 曲目UUID和内容哈希各司其职，重复内容的不同UUID不合并成同一个歌单成员。
5. 保持固定 build/MusicPlayer2.exe 和 build/ 内部输出布局。使用隔离fixture和真实新服务器验证，不请求个人管理员密码或完整Key。
