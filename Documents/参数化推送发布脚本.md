## 调用方式

```powershell
# 本地预览，无网络访问、无标签创建、无推送。
.\publish.bat -Mode Release -Version 0.1.0 -DryRun

# 推送当前分支，等待 Actions 测试与构建；不发布正式 Release。
.\publish.bat -Mode Build

# 版本与说明已提交后，推送分支和版本标签，等待正式发布并验证资产。
.\publish.bat -Mode Release -Version 0.1.0

# 可选：只触发，不等待；使用代理时仅影响本次进程。
.\publish.bat -Mode Build -NoWait -Proxy http://127.0.0.1:7890
```

`-Version` 是核对预期版本，不会自动修改 `client-release.json`。双击 BAT 仅显示用法并暂停；不带 Mode 不推送。命令行自动化可直接调用 `publish.ps1`；BAT 自动化可设置 `MUSIC_PLAYER_NO_PAUSE=1`。

只推送 master/main 当前分支。工作区有未提交文件、当前分支不受工作流支持、远端分支不在本地历史上、已有同名版本标签或 Release 时停止。失败时保留诊断信息；不会删除远端引用或覆盖既有版本。推送已成功后 CI 失败不会自动回滚远程代码。

默认等待上限 60 分钟，轮询间隔 15 秒，可通过 `-TimeoutMinutes`、`-PollSeconds` 调整；`-NoWait` 只报告触发结果，不能视为测试或发布完成。构建模式在远端已是同一提交时可手动触发一次 Actions。正式发布步骤由已有 Actions 实施，本地脚本不绕过测试直接上传 Release。

需要 Git、GitHub CLI，以及可用的 GitHub 登录和推送权限。优先使用现有 GH_TOKEN／GITHUB_TOKEN；否则从 Git 凭据管理器读取当前登录。凭据仅用于进程，不写入脚本、日志或 Git。调用方应设置好 Git 的正常认证。

仅支持 github.com 仓库，调用时显式选择该主机并在结束后恢复原环境。多个 push URL 会被拒绝，避免一次推送意外影响其他仓库。推送失败后不会自动删除已创建的本地标签；脚本会给出标签名，需要先核实远端状态再处理，不能强制覆盖既有发行。

正式 Release 的核验下载放入 Git 忽略的 `test-results/publish/`。它不是运行目录，也不会包含个人播放器配置。开发阶段不需要重复编译播放器或运行整套播放测试。
