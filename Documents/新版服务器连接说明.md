# 连接音乐服务器 0.10.0

播放器的服务器适配版本为 0.10.0，仅使用 `/api/v2`。账号登录、改密、用户与 Key 管理在服务器网页完成，播放器使用账号所属的只读 API Key。

## 配置

1. 在浏览器打开服务器地址，例如 `http://127.0.0.1:8080/`。使用管理员创建的账号登录，首次登录先修改临时密码。
2. 创建播放器用 API Key，保留 `library:read` 和 `media:read` 两项权限。选择自己的私人歌单；若要看到全局曲库，显式勾选系统 `library`。未选择歌单是有效的空授权。
3. 复制创建后只显示一次的 Key。在播放器的「服务器设置」中填写服务器根地址、Key 和缓存目录，然后应用。地址不需要追加 `/api/v2`。
4. 打开「媒体库 → 服务器歌单」，点击刷新。测试连接成功代表 v2 读取接口可用；看到空列表时，检查该 Key 的歌单授权。

同机开发默认地址为 `http://127.0.0.1:8080`。远程部署使用服务器实际 HTTPS 地址。Key 在本机通过 Windows DPAPI 加密保存，不需要放进启动脚本。

## 同步与播放

- 完整接收分页后才保存快照与游标。后续刷新合并增量；授权或歌单成员变化时按服务器要求重建快照。分页期间曲库持续变化，最多重新尝试 3 轮，然后提示稍后刷新。
- UUID 标识曲目，SHA-256 校验下载内容。不同 UUID 即使字节相同也保留独立的歌单成员和缓存路径。成员顺序、歌单说明与个人备注保持一致。
- 浏览和刷新不预下载音频。播放到曲目时按需下载完整文件并校验；已经校验通过的缓存播放不请求服务器。封面和歌词随曲目准备，封面失败不阻断音频。
- 下架或文件缺失的曲目显示 `[不可用]` 占位，保留 UUID、顺序和备注，播放与离线保存会跳过。恢复后刷新即可重新使用。
- 网络连接失败时允许使用最后一次完整快照与缓存；HTTP 错误、无效响应、取消不会当成离线成功。没有完整缓存的曲目会跳过，全部失败会停止。
- 收到 401/403 后记录授权失效，旧远程入口和缓存不能继续作为该 Key 的有效授权。刷新成功后解除限制。账号停用再启用可继续使用原 Key；永久撤销或轮换后需填入新 Key。
- 成功刷新后不再授权的歌单会退出当前播放队列并从最近列表移除。切换服务器或 Key 使用独立缓存命名空间。离线时无法获知尚未收到的远端权限变化；这不是对磁盘文件的 DRM 保护。

本次不兼容旧 `/api/v1` 快照或旧关联歌单。旧缓存不会自动迁移或删除；刷新后重新生成 v2 的关联数据。原音频字节仍留在磁盘，缓存没有自动容量清理。

## 错误提示

| 状态 | 处理 |
| --- | --- |
| 401 | 检查账号是否启用、是否完成首次改密，以及 Key 是否过期、被撤销或轮换。 |
| 403 | 检查 Key 的读取权限和歌单授权。 |
| 404 | 曲目可能未授权、已下架或文件缺失；先刷新。 |
| 429 | 请求或下载达到并发限额，稍后重试。 |
| 网络连接失败 | 可使用最后成功快照和已缓存音频；恢复网络后刷新。 |

## 验证命令

在客户端仓库根目录运行，使用具有 MFC x64 组件的 Visual Studio 2022。构建布局仍遵循[目录规范](客户端文件与构建目录规范.md)，默认程序固定为 `build/MusicPlayer2.exe`。

```powershell
# 原生协议/缓存回归；可选参数会启动独立临时服务器，不访问 8080。
./UnitTest/run-remote-library-cache-tests.ps1 -Python python `
  -ServerBinary 'D:/Develop/Study/MusicPlayer/server/build/musicserver.exe'

# Windows 桌面回归：先关闭其他 MusicPlayer2（程序使用全局单实例锁），输出目录必须尚不存在。
$env:PYTHONDONTWRITEBYTECODE='1'
python UnitTest/remote_playback_desktop.py --exe build/MusicPlayer2.exe `
  --output test-results/desktop-v2-check --empty-default-playlist
```

真实服务集成测试需要同级服务器源码中的 `server/tests/admin-terminal.py`；Windows Python 环境需安装 `pywinpty`，Linux/macOS 则需 `pexpect`。临时数据库、媒体和测试账号会在临时目录中创建，测试进程会在结束时关闭。
