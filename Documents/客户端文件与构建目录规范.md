# 客户端文件与构建目录规范

日期：2026-10-22。适用范围：独立 Git 仓库 `MusicPlayer2/`，Windows C++/MFC 客户端。

本次先整理文件和实际构建输出；播放器功能、服务器协议适配另行开发。沿用服务器固定产物名称、运行数据隔离、Git 管理源码版本的原则。

## 目标目录

```text
MusicPlayer2/
  MusicPlayer2.sln                Visual Studio 解决方案
  MusicPlayer2/                   主程序源码、资源和现有依赖源码
  scintilla/                     编辑器依赖源码
  UnitTest/                      测试源码与验证脚本
  third_party/runtime/           已有第三方运行库输入，按平台/配置分类
  Documents/ Screenshots/        文档与截图
  build-layout.props             公共输出路径
  build-layout.targets           主程序运行依赖与资源复制
  package.bat / package.ps1      分发包入口
  test-results/                  测试程序、测试中间文件、配置和日志；整体忽略
    previous/                    原 build/tests/ 的历史验证产物
  dist/                          固定分发包 MusicPlayer2.zip 和校验文件；整体忽略
  build/                         整体 Git 忽略
    MusicPlayer2.exe              默认 x64 Release 固定程序名
    bass.dll tag.dll ...          对应平台的运行库复制件
    language/ skins/ ...          运行资源复制件
    obj/<项目>/<平台>/<配置>/      中间文件与编译时间资源
    variants/<平台>/<配置>/        其他平台或 Debug 程序
    preserved-data/              清理前单独保留的旧配置/歌单等个人数据
    .old-builds/                  系统拒绝删除后隔离的旧构建，不参与编译
```

默认 x64 Release 输出到 `build/`，其他配置在固定的 `build/variants/<平台>/<配置>/`；程序均名为 `MusicPlayer2.exe`，不增加版本或日期后缀。项目中间文件按项目、平台和配置隔离。测试工程输出改为 `test-results/native/<平台>/<配置>/`，测试中间文件在 `test-results/obj/`，不放入 build/。整个 `build/`、`test-results/`、`dist/` 不提交 Git；第三方 DLL 是构建所需的已有外部输入，不是本项目生成的可执行程序。

源码内的语言、皮肤、图标和第三方依赖源码保留原结构，避免无关的大规模路径修改。根目录旧 `Debug/Release/x64`、源码内旧输出和编译时间文件在保全依赖与个人数据后迁出。用户已授权删除旧构建，但系统自动审批拒绝批量递归删除（仅返回 blocked by policy），因此将其隔离到 `build/.old-builds/`；新构建使用全新的 `build/obj/`，不复用旧对象文件。日常构建只更新程序和资源，不能整体清空含有个人数据的 `build/`。

## 当前构建与验证方法

本次整理先统一 Visual Studio/MSBuild 实际输出，后续可在此基础上添加与服务器一致的 BAT 构建/启动入口。在 Visual Studio 2022 Developer PowerShell 中，从客户端仓库根目录执行：

```powershell
msbuild MusicPlayer2.sln /t:Build /p:Configuration=Release /p:Platform=x64 /p:CL_MPCount=4 /m:4
.\build\MusicPlayer2.exe
```

需使用安装了 C++ MFC 组件的 VS/MSBuild；本机验证使用 Visual Studio 2022 Professional，MSVC 14.44、Windows SDK 10.0.26100.0。单独安装的 Build Tools 没有 MFC，不能据此认为源码缺少文件。

```powershell
python UnitTest/test-build-layout.py --msbuild "<Visual Studio>\MSBuild\Current\Bin\MSBuild.exe"
.\UnitTest\run-remote-library-cache-tests.ps1 -Python python
python UnitTest/remote_playback_desktop.py --exe build/MusicPlayer2.exe --output test-results/desktop --empty-default-playlist
```

桌面测试需要 Windows 交互桌面，输出目录必须为尚不存在的新目录；回归使用自己的 HTTP fixture 和便携配置，不连接当前真实服务器或修改个人 AppData。Python 可设置 `PYTHONDONTWRITEBYTECODE=1` 避免生成源码旁缓存。运行中的客户端应先退出，再更新同一路径的程序。

分发时运行 `package.bat`，只发送生成的 `dist/MusicPlayer2.zip`；不要直接复制整个 build/。测试和个人数据通过文件白名单排除，细节见[客户端打包与分发](客户端打包与分发.md)。原 build/tests/ 已整体迁至 test-results/previous/。
